# Architecture
Layers (arrows = allowed imports): ui -> api -> core -> platform(interface). linux/windows/fake implement the interface.
- core/: scanner, tree, aggregation, models. Pure Python.
- platform/: `Platform` ABC (base.py): stat, scandir (size on disk, hard-link ids), list_volumes, owner_and_perms, created (birth time or None), is_hidden, trash (TrashUnavailableError when a drive has no Trash), reveal. local.py = shared os.scandir/send2trash base; linux.py, windows.py (stubs until Stage 7), fake.py. Chosen at startup by sys.platform; tests use fake.
- Hot-plug: core/volumes.py `VolumeWatcher` polls list_volumes every few seconds only while resumed (window visible).
- api/: thin pywebview bridge (bridge.py `Api`). Plain dicts only; errors are `{ok: false, error: {code, message}}`, never exceptions. Paths cross as segment lists relative to the scan root; breadcrumbs = root path parts (not navigable) + segments. Long work runs in threads, results pushed as events via `window.duaEvent(event, payload)`. Methods: list_volumes, scan(location), cancel_scan, get_children(segments, sort, limit, on_disk) (works mid-scan on the live tree: `partial: true`; each item has `problem`: denied/unreadable/other_drive/null), get_details (file view: path, size_on_disk, created, owner/group/mode, read_only_drive, `trash_blocked` = plain-language reason or null), get_usage (with `level`: ok/filling/low/full), open_in_file_manager, move_to_trash(segments, confirmed=True) (updates totals in place; failures read_only/permission/no_trash/not_found/drive_unavailable in plain words), get_prefs/set_theme, set_visible.
- app.py: creates the window, wires window events (shown/minimized/restored -> set_visible, closed -> shutdown). `--demo` uses platform/demo.py (generated tree on fake drives).
- ui/: index.html, app.css (tokens as CSS vars), app.js (vanilla ES modules), fonts/. State = one object, render functions per panel (top, breadcrumb, usage, list + notice + empty/error states, side panel). While scanning, the open folder is re-fetched on progress events (<= ~1/s, not while hidden). app.js resolves the theme (OS preference or override) to data-theme=light|dark.

Models (core/models.py, dataclasses): Node(name, size, size_on_disk, is_dir, mtime, child_count; Created is read on demand by get_details, not stored), ScanWarning, ScanProgress, ScanResult. Volume and Permissions live in platform/base.py (platform may not import core) and are re-exported from core/models.
`Scanner.result` is the live ScanResult; sizes are pushed up to ancestors as each folder is listed. Tree is stored compactly (arrays/slots, interned names); only top-N children per folder are sent to the UI.
Events: scan_progress, scan_done, volumes_changed, error.
