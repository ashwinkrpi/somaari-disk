# Decisions
Format: `- [date] decision - reason`
- [2026-10-01] Python core + pywebview + vanilla HTML/CSS/JS UI - reuses the HTML design, light on Pi, same code on Windows (WebView2).
- [2026-10-01] Only write operation is Move to Trash - safe for public release.
- [2026-10-01] Linux window backend = pywebview 6.2.1 GTK + WebKitGTK 4.1 - spike passed on Pi 5 (Debian 12 arm64, X11): window opens, page renders, ~160 MB RSS. Chromium --app fallback not needed.
- [2026-10-01] Linux setup: apt `python3-gi` `python3-venv` `gir1.2-webkit2-4.1` (pulls `libwebkit2gtk-4.1-0`); venv must use `--system-site-packages` so PyGObject comes from apt, not pip (no build toolchain needed).
- [2026-10-01] Build backend hatchling, src/ layout - standard, no setup.py.
- [2026-10-01] psutil/send2trash not declared until the stage that uses them - keep Stage 0 deps minimal.
- [2026-10-01] CI installs the package with --no-deps (no pywebview) - tests are core-only and never open windows; avoids GUI deps on runners.
- [2026-10-01] Git commits use the GitHub noreply address via repo-local config - no personal email in history.
- [2026-10-01] PSF-2.0 added to allowed licenses - permissive; needed for typing_extensions (pywebview dep).
- [2026-10-01] Stage 1 adds a minimal Platform ABC (stat, scandir) + LocalPlatform (os.scandir, Linux and Windows) + FakePlatform - core may not import os; Stage 2 extends the ABC and splits linux/windows.
- [2026-10-01] Scanner workers only list directories; the scan thread builds the tree - no locks on tree or hard-link set.
- [2026-10-01] Folder apparent size = sum of contents; size on disk also counts the folder's own blocks (like du). Size on disk = st_blocks*512, falling back to apparent size where st_blocks is missing (Windows, until Stage 7).
- [2026-10-01] Repeat hard links stay in the tree with size 0 (counted once per (dev, inode)). Symlinks and reparse-point dirs are skipped and counted, not shown.
- [2026-10-01] Dirs on another filesystem appear empty with an other_filesystem warning unless cross_mounts=True.
- [2026-10-01] Stage 2: psutil + send2trash declared as dependencies (both BSD-3-Clause, already in THIRD-PARTY-NOTICES); psutil for the mount table/usage (comes from apt on the Pi), send2trash for per-volume trash on Linux and Recycle Bin on Windows. Both lazy-imported; CI tests stub them.
- [2026-10-01] Volume and Permissions dataclasses live in platform/base.py, re-exported by core/models - platform must not import core.
- [2026-10-01] Hot-plug = core VolumeWatcher polling Platform.list_volumes (default 3 s) instead of a per-platform watch_volumes - one implementation for all OSes, testable with fake; paused watcher blocks on an Event (0 CPU). Change = volume added/removed/relabelled/remounted, not free-space drift.
- [2026-10-01] LocalPlatform is now an abstract shared base; get_platform() picks LinuxPlatform or WindowsPlatform. test_scanner_local switched to get_platform() because LocalPlatform can no longer be instantiated.
- [2026-10-01] Volume lost mid-scan: partial result with volume_lost=True and one volume_lost warning, workers not awaited (may hang on a dead device); CLI exit code 2.
- [2026-10-01] reveal opens the containing folder with xdg-open; it cannot select the file. Trash refuses volume roots and items in read-only folders before calling send2trash.

- [2026-10-01] Stage 3: api errors are dicts with a code + plain-language message; a `_guard` decorator maps ApiError/OSError (EROFS -> read_only, EACCES -> permission, ENOENT -> not_found) - the UI never sees exceptions.
- [2026-10-01] One scan at a time; a new scan cancels the previous one and superseded scans never report. The tree is only exposed after scan_done (no reads during a scan) - no locks needed in the scanner; progressive list fill is Stage 4.
- [2026-10-01] Locations = volumes from list_volumes + "Home folder" (Path.home()); the app auto-scans Home (else the system volume) on start.
- [2026-10-01] move_to_trash requires confirmed=True from the caller and refuses read-only volumes and the scan root; on success the node is removed and ancestor totals updated (no rescan).
- [2026-10-01] Theme override persisted in platformdirs user_config_dir/prefs.json (only file the app writes besides Trash); pywebview private_mode stays on, so no localStorage.
- [2026-10-01] Theme override control = a compact select in the top panel (not in the boards) - spec needs a manual override and the boards show none.
- [2026-10-01] Top panel controls use the dark control tokens in both themes - the panel is dark in both palettes. Dark usage-state colors derived (warn #D9A93A/#F2CF7A, low #E8893A/#F5B27A, full #E05252/#F2B8B5); contrast check in Stage 5.
- [2026-10-01] Name sort = casefold then code point (core is locale-free); the UI may re-sort with Intl.Collator if needed.
- [2026-10-01] Guarded api methods carry `__signature__` - pywebview builds JS stubs from getfullargspec, which ignores __wrapped__.
- [2026-10-01] Fonts: @font-face tries locally installed IBM Plex first, then ui/fonts/*.woff2, then system-ui. 2026-10-04: woff2 files (Sans 400/500/600, Mono 500) + OFL.txt bundled from the official IBM/plex GitHub releases (plex-sans 1.1.0, plex-mono 2.5.0).
- [2026-10-01] Scanner adds each listed folder's sizes to all ancestors (once per folder, not per file) instead of a final bottom-up pass - the live tree stays consistent, so the list can fill in during a scan at O(dirs x depth) cost.
- [2026-10-01] Live reads (get_children, get_details) use the running scan's tree; open_in_file_manager/move_to_trash still need a finished scan - trash would race the scanner thread mutating the tree.
- [2026-10-01] Usage level computed in Python (`usage_level`), labels/icons in the UI; "Disk full" = 100% used OR no free space - ext4 reserved blocks leave users at 0 free while used% is ~95%; total 0 = no warning.
- [2026-10-01] Unreadable folders flagged per item from scan warnings (`problem`: denied/unreadable/other_drive) - lets the list say "No access" instead of showing a silent 0 B.
- [2026-10-01] Rescan keeps the open folder (falls back to root if it is gone); changing location starts at root. Backspace = Up (except in selects), Enter opens a folder, arrows/Home/End/PgUp/PgDn move the selection.
- [2026-10-01] File selection shows a light summary (type, size, shares, modified) in the right panel; full "File details" + actions are Stage 5.
- [2026-10-01] Created = filesystem birth time, read on demand via Platform.created (Linux: glibc statx through ctypes, Python 3.11 has no st_birthtime there; Windows/macOS: st_birthtime). Never ctime (that is change time). Unknown -> "Unknown" in the UI. Not stored in Node - keeps the tree compact.
- [2026-10-01] Show in folder: files go through org.freedesktop.FileManager1.ShowItems via `gdbus` (2 s timeout; URI percent-encoded so no quoting issues), falling back to xdg-open of the parent folder; folders open directly. No new dependency.
- [2026-10-01] Move to Trash UI: native <dialog> (modal, Esc = cancel, Cancel focused first) with name + size; button disabled with the reason when get_details.trash_blocked is set (scan root, scan running, read-only drive). Delete key on a file row opens the same dialog. After success the next row is selected and the folder/usage are re-read (tree totals already updated by the api).
- [2026-10-01] Trash failures mapped to plain-language codes: no_trash (send2trash TrashPermissionError -> TrashUnavailableError), drive_unavailable (ENODEV/ENXIO), read_only, permission, not_found (item removed outside the app: also dropped from the tree so totals stay right), other errors "Couldn't move this item to the Trash: <reason>."
- [2026-10-01] The scanned drive's read-only flag is cached per scan (one list_volumes per scan) - get_details runs on every selection and list_volumes runs lsblk on Linux. move_to_trash still re-checks live volumes.
- [2026-10-01] WCAG AA checked by a test that computes contrast for text (4.5:1) and focus-ring (3:1) token pairs in light and dark - every pair passed with the existing tokens; added --on-destructive (#FFFFFF light, #0F141B dark) for the filled Move to Trash button.

- [2026-10-01] Saved scans: gzip JSON Lines, one node per line, written and read as streams so a 1M-file tree never exists twice in memory (nested JSON would need a full second copy). gzip level 1: on the Pi, speed matters more than the last few MB. Format version in the header; a broken/truncated file (no trailing "end") is deleted and the app rescans. No new dependency.
- [2026-10-01] Startup and Location change open the saved scan with a dated notice; Rescan/F5 always scans fresh. Only complete scans are saved. File names are hashes of the location id, so odd ids need no escaping.
- [2026-10-01] Volume id = `uuid:<filesystem UUID>` from lsblk (falls back to device path; a second volume with the same UUID, e.g. a cloned card, keeps its device path). The id survives replug to another /dev node; the cached tree is re-rooted to the current mount point.
- [2026-10-01] Scanner keeps at most workers x 2 folder listings in the thread pool and the rest in a depth-first stack. Submitting every folder on discovery left one Future (~1 KiB with its Condition) per queued folder: 1M-file bench went from 44.5 s / 1.55 GiB peak to 8.9 s / 527 MiB peak (peak includes the generated input tree).
- [2026-10-01] Names deduped with a per-scan dict instead of sys.intern: same sharing, and the dict is freed after the scan (the intern table cost ~50 B per unique name for the tree's lifetime).
- [2026-10-01] Memory budget (bench, Pi 5): scan tree ~133 B/node when names/ints are shared, ~250-300 B/node on a real disk (Node 88 + name ~60 + 3 ints 84). 1M files ~ 250-300 MiB. Saved scan for 1M files: 14 MiB, save 6 s, load 5.5 s. Acceptable for the ~2 GiB budget; no array-packed tree yet.
- [2026-10-01] Non-UTF-8 names stay as surrogate-escaped str end to end (they reopen the real file). JSON to the UI is ASCII-escaped; display_name() swaps bad bytes for U+FFFD where text must be printed (CLI). find_node accepts the U+FFFD form when exactly one child matches, in case the webview bridge normalizes lone surrogates.
- [2026-10-01] Log: stdlib RotatingFileHandler (512 KiB x 4) in the platformdirs config dir; errors="backslashreplace" so odd names cannot break logging. Unexpected api exceptions are logged with traceback and returned as code "internal".
- [2026-10-01] Windows OS calls via stdlib ctypes (kernel32/advapi32/user32), not pywin32 - no new dependency, no license or wheel concerns on ARM64 Windows; the calls are few and wrapped in platform/windows.py with argtypes set.
- [2026-10-01] Windows size on disk = size rounded up to the volume cluster size; GetCompressedFileSizeW only for compressed/sparse/offline/cloud-placeholder files - one extra syscall per file instead of two. Small files resident in the MFT are over-counted by one cluster.
- [2026-10-01] Windows scandir re-stats each regular file (os.lstat) for file index, link count and volume serial - DirEntry.stat lacks them; needed to count hard links once (WinSxS). Costs one open per file on Windows only.
- [2026-10-01] Windows volume id = volume GUID (stable per machine, survives replug), else volume serial - same "survives replug" goal as Linux fs UUIDs.
- [2026-10-01] WebView2 runtime checked in the registry before pywebview loads; missing runtime = native dialog + exit 1 - pywebview's own error is a traceback.
- [2026-10-01] App renamed to somaari-disk (distribution, CLI, platformdirs folders), package somaari_disk - a hyphen is not valid in a Python import name. Saved scans/logs in the old disk-usage-analyzer folders are not migrated: the app rescans; old folders can be deleted by hand.

- [2026-10-04] Linux release = one `Architecture: all` .deb built with dpkg-deb: GTK/WebKitGTK/PyGObject/psutil from apt (Depends), pure-Python deps vendored in /usr/lib/somaari-disk, bytecode compiled in postinst - freezing GTK/WebKit is fragile on ARM and huge; system Python + apt libs gets security updates. The build fails if any compiled file is vendored. pywebview's Windows/Android binaries (webview/lib) are pruned.
- [2026-10-04] Windows release = PyInstaller folder build (zip) + Inno Setup per-user installer (no admin) - pywebview documents and hooks PyInstaller (pythonnet + WebView2 DLLs). PyInstaller is GPL-2.0 with a bootloader exception: build-time only and the output may use any license, so the permissive-only rule holds for what we ship; approved by the owner. cx_Freeze (permissive) was the alternative, less proven with pywebview.
- [2026-10-04] `packaging` (Apache-2.0/BSD) added to dev extras for the dependency-license test; `build` used only in the release workflow - build/test tools, not shipped.
- [2026-10-04] Release workflow publishes a DRAFT GitHub Release (sdist, wheel, .deb, Windows zip + setup.exe, SHA256SUMS); a human publishes it - nothing goes public by automation.
- [2026-10-04] App icon: three decreasing bars on the top-panel navy (design tokens), SVG source + committed PNG/ICO (packaging/icons/make_icons.py, rsvg-convert) - release builds need no image tools.
- [2026-10-04] Top-panel selects use `appearance: none` + a CSS-gradient chevron - WebKitGTK painted them from the GTK theme (light background, light text in the light theme). A data-URI SVG chevron would contain an xmlns URL that the no-network test rejects.
- [2026-10-04] Display name "Somaari Disk" everywhere (window title, page heading, menu entry, installer, WebView2 dialog); .desktop GenericName stays "Disk Usage" so menus can show what it does - owner chose one name.
- [2026-10-04] Release workflow also builds on every push to main (doc-only changes skipped); the builds are run artifacts, and only v* tags make a draft release - test builds without cutting a release. Costs Actions minutes while the repo is private (Windows counts 2x).
- [2026-10-04] Multi-select in the list like a desktop file manager (click, Ctrl+click toggle, Shift+click range from an anchor, Ctrl+Shift+click adds a range, Shift+arrows, Ctrl+A, Esc back to one); rules in a pure ui/selection.js tested under node - testable without a browser, keeps app.js DOM-only
- [2026-10-04] Several selected rows: details panel lists every name and size with the total; Move to Trash takes the selected files only (folders skipped, same rule as Delete on one row), one confirmation listing them, then the existing move_to_trash per file (no new api) - one call per item keeps the per-item read-only/not-found handling; an already-gone file counts as done
- [2026-10-04] Full keyboard access: arrow keys move between buttons in button groups only (trash dialog, details-panel actions, breadcrumb; rules in pure ui/keys.js), not in the top bar where arrows must keep changing a select; F6/Shift+F6 cycle top bar, list, details panel (Explorer's F6); Ctrl+arrows move focus without selecting and Ctrl+Space toggles (keyboard Ctrl+click), shown with a dashed focus ring; name lists are tab stops so they scroll by keyboard; details-panel re-renders put focus back on the same action - a user without a mouse can do everything
- [2026-10-04] Every push goes through scripts/ship.py: patch bump, a "Version X.Y.Z" commit holding only pyproject.toml + __init__.py, then push; minor/major/X.Y.Z on request; no automatic tags - a pre-push hook can't add a commit to the push in progress and a CI bump commit would have to be pulled back; tags start the release workflow, so releases stay deliberate. Version stays in both files (release workflow and tests read pyproject.toml), kept equal by the script and test_versions_agree
- [2026-10-04] ship.py also sets a README shields.io version badge in the bump commit, if the README has one (this repo's doesn't, so nothing changes here) - kept identical to somaari-ai's copy, whose badge went stale when edited by hand
- [2026-10-04] Folders can go to the Trash (side panel button, Delete key, multi-select mixed with files), same move_to_trash per item. The dialog warns that everything inside goes too. Show in folder for folders still not added.
- [2026-10-11] Window size/position/maximized saved to window.json in the config dir, written once after the window closes (no polling). Position skipped on Wayland. Changes within 0.5 s before a "maximized" event are undone because maximizing fires resize/move first on some backends; normal size kept while maximized. `--reset-window` deletes the file - recovery when a monitor change leaves the window unreachable

- History audit 2026-10-04: no secrets, hostnames, IPs or personal paths in any commit; only the LICENSE name and the noreply author email. No rewrite needed. Re-checked 2026-10-08 after the filter-repo rewrite: still clean (only the `/home/someone` test sample path).
- [2026-10-08] Dev-only files kept local, not in the public repo: CLAUDE.md, .claude/, docs/BUILD-PLAN.md, design/boards/ (untracked + gitignored), and removed from all past commits and tags with git filter-repo (force-pushed 2026-10-08).
- [2026-10-08] Dependabot (`.github/dependabot.yml`): pip + github-actions, monthly - keeps deps and pinned actions current without noise; PRs still need CI green and a license check (THIRD-PARTY-NOTICES).

Dependabot security alerts (repo setting) stay on.

## Deferred
- lsblk mount-point matching for LVM/LUKS mappers - needs that hardware; UUID ids done in Stage 6.
- Memory check on a large real volume (bench covers a generated 1M tree) - manual, see TESTING.md.
- Undo / restore from Trash inside the app - not planned; the OS Trash restores.
- Sort control and size-on-disk toggle for the list (api supports both) - not in Stage 4 boards; add if wanted.
- Cache the problems map per scan instead of rebuilding from warnings on each get_children - only if a real many-warning scan proves slow.
- Array-packed tree (sizes/mtimes in array.array) to cut ~85 B/node - only if real volumes exceed the memory budget.
- Saved-scan staleness hint (e.g. drive free space changed since the scan) - not in plan.
- Window min size 1024x600 set; visual check vs boards at 1280x800 / 1024x600 needs a human (Stage 4 screens).
- Windows: volumes mounted in folders (no drive letter) are not listed - rare; needs FindFirstVolume/GetVolumePathNamesForVolumeName.
- Windows: owner of a symlink/junction shows the target's owner (GetNamedSecurityInfoW follows links) - needs a handle opened with FILE_FLAG_OPEN_REPARSE_POINT.
- Windows: MFT-resident small files counted as one cluster on disk - needs FSCTL queries; not worth it.
- WebView2 bootstrapper in the installer (Inno Setup registry check + silent per-user run) - only if Windows 10 users report the missing-WebView2 message. Code signing: not for now (unsigned, 2026-10-08).
- .deb for Python 3.10 distros (Ubuntu 22.04) and rpm/AppImage/Flatpak - not planned; docs/GUIDE.md covers source installs.
- Windows ARM64 build - no arm64 runner job yet; x64 build runs under emulation.
